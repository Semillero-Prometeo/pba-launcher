# **1.1. Contexto del Proyecto** 

El androide “R-ONE” es un proyecto planteado y desarrollado por el semillero de investigación PROMETEO, en la facultad de ingeniería de sistemas de la Universidad Libre de Colombia sede El Bosque (en Bogotá). 

El proyecto tiene como objetivo realizar un acercamiento transversal para todos los miembros de la universidad libre con robots humanoides, automatizando procesos repetitivos

El proyecto consiste en el diseño e implementación de un sistema inteligente multicámara en tiempo real capaz de detectar y Re identificar personas mediante modelos de visión artificial (YOLO + ReID), interpretar el contexto visual utilizando un modelo Vision-Language multimodal compacto, y generar respuestas autónomas tanto verbales (mediante síntesis de voz 

local) como físicas (a través de Arduino), todo ejecutado en una arquitectura Edge optimizada que integra percepción, interpretación semántica y acción en un entorno unificado de procesamiento local. 

Así mismo, el desarrollo y unificación de los aplicativos móviles y web del semillero 

como conjunto integro al ecosistema tecnológico del semillero de investigación.

# **_4.3.1. ¿Qué es Angular?_** 

Es un _framework_ (marco de trabajo) para la construcción de aplicaciones web. Un framework puede entenderse como un molde o plantilla: proporciona la estructura, las reglas y las herramientas necesarias para que las personas desarrolladoras trabajen con mayor rapidez y orden, sin necesidad de concebir cada elemento desde cero. 

Si construir una aplicación web equivaliera a edificar una casa, Angular sería el conjunto de herramientas de construcción —nivel, plomada, normas de seguridad— que garantizan que el resultado sea sólido y predecible. 

Angular organiza la aplicación en componentes, que son piezas reutilizables de la 

interfaz. Cada componente integra una clase TypeScript que contiene la lógica, una plantilla 

HTML que define la vista y hojas de estilo CSS que determinan el diseño visual. 

Página 29 

# **_4.3.2. ¿Qué es TypeScript?_** 

Es una extensión del lenguaje JavaScript que incorpora tipos estáticos. Esto significa que el programador debe declarar qué clase de dato maneja cada variable: texto, número, valor booleano, objeto con una forma específica, etcétera. 

JavaScript es comparable a escribir sobre papel en blanco; TypeScript, a escribir sobre papel pautado con renglones y márgenes. Impone más restricciones, pero el resultado es más ordenado y menos propenso al error.

# **_4.3.3. ¿Qué son los Componentes Standalone?_** 

En versiones anteriores de Angular era obligatorio agrupar los componentes en módulos (NgModules) para que pudieran compartir dependencias. A partir de Angular 14 existe el modo Standalone (independiente), en el cual cada componente declara directamente sus propias dependencias sin requerir un módulo intermediario. Este proyecto emplea exclusivamente el modo Standalone, que constituye la forma moderna y recomendada de construir aplicaciones Angular. 

Página 30 

# **_4.3.4. ¿Qué son los Angular Signals?_** 

Los **Signals** constituyen el nuevo sistema de reactividad de Angular. Un Signal es un contenedor de valor que notifica de manera automática a todos sus observadores cuando dicho valor cambia, lo que permite actualizar la interfaz de forma eficiente. 

Imagínese un semáforo conectado a una pizarra electrónica. Cuando el semáforo cambia de rojo a verde (cambio de estado), la pizarra se actualiza automáticamente (componente reactivo). Ese semáforo desempeña el papel de un Signal. 

El proyecto emplea tres variantes: signal(valorInicial), que es un Signal mutable; computed(() => …), un Signal derivado que calcula su valor a partir de otros; y effect(() => …), un efecto secundario que se ejecuta cada vez que cambian sus signals dependientes. 

# **_4.3.5. ¿Qué es RxJS?_** 

(Reactive Extensions for JavaScript) es una biblioteca destinada al manejo de flujos de 

datos asíncronos. En lugar de operar con un valor que llega una sola vez —como ocurre con una variable—, RxJS trabaja con Observables: flujos de valores que pueden llegar en cualquier momento, en múltiples ocasiones y desde diversas fuentes. 

Un Observable se asemeja a un canal de televisión que emite contenido de forma continua. El consumidor puede suscribirse para recibir lo que se transmite, filtrar la señal, transformarla o combinarla con la de otros canales antes de recibirla. En este proyecto, RxJS se emplea principalmente para gestionar las llamadas HTTP al backend, cuya respuesta no es inmediata.

# **_4.3.6. ¿Qué son los Microservicios?_** 

El backend de Prometeo se halla dividido en microservicios: programas pequeños e independientes, cada uno responsable de un área específica. Su principal ventaja radica en que pueden desarrollarse, desplegarse y escalarse de manera autónoma. 

El frontend interactúa con cuatro de ellos: pba-ms-auth (autenticación de usuarios), pbams-management (gestión de usuarios y roles), pba-ms-robotics (control del hardware robótico) y pmai-mai-core o MAI Core (núcleo de inteligencia artificial).

# **4.6. Sistema de Autenticación y Autorización** 

La autenticación responde a la pregunta ¿quién eres? (verificación de identidad), mientras 

que la autorización responde a «¿qué puedes hacer?» (permisos y roles). Este sistema emplea JWT (JSON Web Tokens) para la autenticación. Un JWT es un texto codificado que el servidor 

genera cuando el usuario inicia sesión y que el cliente adjunta en cada petición posterior para acreditar su identidad. 

Página 37

vez que se desea entrar a una zona, el personal de seguridad (servidor) verifica la pulsera sin necesidad de solicitar nuevamente la identidad.

El flujo de inicio de sesión se desarrolla en una secuencia ordenada de pasos: 

El método login() envía una petición POST a /auth/login con el usuario y la contraseña. 

Al recibir el accessToken, lo almacena en localStorage y actualiza el signal de token. 

A continuación, una petición GET a /auth/me carga el perfil y actualiza el signal correspondiente. 

Si el usuario posee un único rol, este se confirma de forma automática; si posee varios, el sistema presenta un selector y espera la elección. 

Una vez elegido el rol, confirmRole(roleId) almacena la selección y la transmite a todas las peticiones posteriores mediante la cabecera X-Active-Role, que el interceptor añade de forma automática.

# **_4.6.3. El Interceptor de Autenticación_** 

Un interceptor HTTP es un componente que intercepta todas las peticiones antes de que salgan y todas las respuestas antes de que lleguen al componente solicitante. Equivale a un asistente que, antes de enviar cualquier carta, añade automáticamente el membrete y el sello; y que, al recibir la correspondencia, la abre primero y advierte de cualquier problema urgente. 

Al salir una petición, el interceptor añade las cabeceras de autenticación; al recibir una respuesta con código 401 (no autorizado), muestra el mensaje «Sesión inactiva» y ejecuta el cierre de sesión automático. 

# **_4.6.4. Guards de Ruta_** 

Los Guards son funciones que Angular ejecuta antes de permitir la navegación hacia una ruta; si el guard devuelve un valor falso o una redirección, la navegación se cancela. 

El authGuard protege las rutas reservadas a usuarios autenticados: si el usuario lo está, permite el acceso; en caso contrario, lo redirige a /login. El guestGuard cumple la función inversa, protegiendo las rutas de inicio de sesión y registro frente a usuarios que ya disponen de una sesión activa.
